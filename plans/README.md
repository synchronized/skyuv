# skyuv 开发计划

`plans/` 保存各阶段可执行的开发计划。长期方向和阶段关系由 [`docs/ROADMAP.md`](../docs/ROADMAP.md) 维护；计划文档负责说明某个阶段具体如何实施、验证和收尾。

## 状态定义

| 状态 | 含义 |
|---|---|
| 草案 | 仍有影响实施方式的未决问题，尚未开始编码 |
| 就绪 | 目标、范围和验收标准已经明确，可以开始实施 |
| 进行中 | 已经开始编码或验证 |
| 暂停 | 主动停止，文档中必须说明原因和恢复条件 |
| 已完成 | 验收标准全部满足，完成记录已经补齐 |

同一时间原则上只有一个阶段计划处于“进行中”。确实可以独立推进的工作，应在计划中明确依赖关系后再并行执行。

## 计划文档要求

每份计划至少包含：

- 状态；
- 背景；
- 目标；
- 不在范围内；
- 设计决策；
- 影响范围；
- 实施步骤；
- 测试方案；
- 验收标准；
- 风险与回退；
- 未决问题；
- 完成记录。

计划中的任务应按可独立验证的顺序拆分。不得仅以“代码已经编写”作为完成标准，必须给出可重复执行的构建、测试或行为对照方法。

## 维护规则

- 开始实施前，将状态从“草案”更新为“就绪”，并解决会改变架构方向的未决问题。
- 首个实现提交产生后，将状态更新为“进行中”。
- 实施过程中发现范围变化时，先更新计划，再扩大代码修改范围。
- 完成时记录实际结果、关键提交、与原计划的差异及遗留问题。
- 已完成计划保留在仓库中，不改写成事后看起来完全线性的过程。
- 跨阶段且长期有效的决策，应同步更新路线图或依赖决策文档。
