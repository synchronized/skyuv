# 011：client.socket 的 libuv 改造

## 状态

草案。已梳理现有接口，尚未开始实现。独立 Windows Lua 的 Winsock 初始化和连接错误
诊断已先行修复；本计划负责后续整体迁移，不改写修复记录。

## 背景与目标

便携 client 模块目前复用经过补丁适配的上游原生 socket 实现，仍包含 Winsock/BSD socket
分支。改用 libuv TCP 和事件循环，保留 `connect`、`send`、`recv`、`close`、`shutdown`、
`select`/`poll`、`usleep`、`readstdin` 的 Lua 使用方式和已测试行为。
保持统一 `client.dll/client.so` 和 `client.crypt`，不改造 Skynet Actor 调度。

## 设计方向与影响范围

- 自有网络实现放在 `src/`，平台例外收敛在 `src/platform/`，不直接修改第三方源码。
- 每个 Lua 模块状态独占客户端 loop；同一 loop 的创建、运行、关闭由使用它的线程执行。
  必须核对 Skynet 服务跨 worker 迁移时的线程归属，再决定专属 I/O 线程或串行调用方案。
- `connect` 等待连接回调后返回；`send` 等待写完成；`recv` 通过非阻塞 loop 推进接收，
  无数据不返回值，EOF 返回空字符串。回调只记录状态，不调用可能 longjmp 的 Lua API。
- 整数参数表示模块管理的连接 ID，不保证等于系统 fd/SOCKET；检查下游是否依赖原生句柄。
  ID 不得让迟到回调命中已复用连接，关闭允许安全重复调用。
- `select/poll` 以接收队列、EOF、错误和写状态判断就绪，通过 loop 与定时器等待，
  处理重复 ID、无效 ID、空表、零超时和无限等待，不混用 uv_poll 与正在运行的 uv_tcp。
- `shutdown("w")` 使用 uv_shutdown；读关闭须明确停止读取、释放缓存、后续 recv 与
  rw 组合语义，与上游对照后决定是否需要极小的平台扩展。
- Lua 状态销毁时完成关闭回调、释放连接及缓存，再销毁 loop；有界接收缓存避免无限增长。
- stdin 现有状态协议保持不变，明确后台线程与模块销毁的所有权，避免新实现引入退出挂起。
- CMake 替换便携客户端 socket 源码；保留上游 Linux 基线目标，以便行为对照。
  自有目标使用 skyuv 严格警告策略，不能把该策略施加到混合编译的 crypt 第三方源码。

## 实施步骤与测试方案

1. 审计下游整数句柄用法、worker 线程迁移、读半关闭语义，解决未决问题后将状态改为就绪。
2. 实现 loop 与连接生命周期、同步连接与错误路径、非阻塞接收和完整发送。
3. 接入 shutdown、select/poll、休眠与 Lua GC，保持 crypt 独立于客户端网络状态。
4. 增加独立解释器回环和拒绝连接测试，覆盖多连接、重复关闭、GC、未完成写入、背压、
   EOF、半关闭、就绪等待及退出；并进行重复和压力测试。
5. Windows 配置、构建与 CTest 通过后推送，手动触发 Linux/macOS CI，查看最终结论。

## 验收标准与风险回退

既有客户端和 stdin 测试通过，新增生命周期和压力测试通过，三平台独立解释器可运行；
没有泄漏、悬挂 loop 或已知退出挂起。诊断保留目标地址、端口、libuv 错误名和原因。
明确记录连接 ID 与原生句柄的差异和读半关闭边界。迁移分步提交，可回退到原补丁实现。

## 未决问题与完成摘要

兼容需求、stdin 阻塞读取的销毁方案。当前只有设计规划，不能宣称客户端已改用 libuv。
