# 011：client.socket 的 libuv 改造

## 状态

进行中，纳入 `v0.2.0-beta.3`。2026-10-12 用户确认下游不使用原生句柄，也不使用
`shutdown("r")`，并接受建议的兼容方案。已实现独立运行时的线程、命令与关闭基础。
独立 Windows Lua 的 Winsock 初始化和连接错误
诊断已先行修复；本计划负责后续整体迁移，不改写修复记录。

## 背景与目标

便携 client 模块目前复用经过补丁适配的上游原生 socket 实现，仍包含 Winsock/BSD socket
分支。改用 libuv TCP 和事件循环，保留 `connect`、`send`、`recv`、`close`、`shutdown`、
`select`/`poll`、`usleep`、`readstdin` 的 Lua 使用方式和已测试行为。
保持统一 `client.dll/client.so` 和 `client.crypt`，不改造 Skynet Actor 调度。

## 设计方向与影响范围

- 自有网络实现放在 `src/`，平台例外收敛在 `src/platform/`，不直接修改第三方源码。
- 每个 Lua 模块实例按需启动一个专属 I/O 线程，由该线程独占 loop；Lua 调用通过受锁保护的
  命令队列和 uv_async 唤醒提交操作，结果通过条件变量通知。加载模块时不创建线程。
  服务迁移 worker 不改变 loop 归属；I/O 线程不得调用 Lua API，也不得等待 Lua 线程反向执行操作。
- `connect` 等待连接回调后返回；`send` 等待写完成；`recv` 非阻塞地消费接收队列，
  无数据不返回值，EOF 返回空字符串。回调只记录状态，不调用可能 longjmp 的 Lua API。
- 整数参数表示模块管理的连接 ID，不保证等于系统 fd/SOCKET；下游已确认不依赖原生句柄。
  ID 不得让迟到回调命中已复用连接，关闭允许安全重复调用。
- `select/poll` 以接收队列、EOF、错误和写状态判断就绪，通过 loop 与定时器等待，
  处理重复 ID、无效 ID、空表、零超时和无限等待，不混用 uv_poll 与正在运行的 uv_tcp。
- `shutdown("w")` 在已接受写请求完成后使用 uv_shutdown，仍允许读取响应。
  尽管下游未使用读半关闭，首版保留 r/rw 接口：通过最小平台适配执行原生读半关闭，
  不以 uv_read_stop 代替；缓存、后续 recv 和重复调用行为以三平台上游对照测试为准。
- connect 增加可选超时参数，旧二参数调用保持现有等待行为；有限超时必须取消连接并释放资源。
  首版不增加收发超时、DNS 或 IPv6，保持现有 IPv4 地址连接范围。
- 接收缓存采用每连接固定上限，到上限暂停读取，消费后恢复，不丢数据；具体数值在实现时
  根据背压测试确定并记录。select 写就绪表示可以接受发送，不表示对端已收到数据。
- Lua 状态销毁时完成关闭回调、释放连接及缓存，再销毁 loop；有界接收缓存避免无限增长。
- stdin 保持现有 API 和状态协议，不进行整体重写；必须审计阻塞线程与实例销毁的所有权，
  单独测试退出行为，不允许网络迁移引入退出挂起或 use-after-free。
- CMake 替换便携客户端 socket 源码；保留上游 Linux 基线目标，以便行为对照。
  自有目标使用 skyuv 严格警告策略，不能把该策略施加到混合编译的 crypt 第三方源码。

## 实施步骤与测试方案

1. 根据已确认边界实现专属 I/O 线程；先固定读半关闭对照结果及 stdin 所有权规则。
2. 实现 loop 与连接生命周期、同步连接与错误路径、非阻塞接收和完整发送。
3. 接入 shutdown、select/poll、休眠与 Lua GC，保持 crypt 独立于客户端网络状态。
4. 增加独立解释器回环和拒绝连接测试，覆盖多连接、重复关闭、GC、未完成写入、背压、
   EOF、半关闭、就绪等待及退出；并进行重复和压力测试。
5. Windows 配置、构建与 CTest 通过后推送，手动触发 Linux/macOS CI，查看最终结论。

## 验收标准与风险回退

既有客户端和 stdin 测试通过，新增生命周期和压力测试通过，三平台独立解释器可运行；
没有泄漏、悬挂 loop 或已知退出挂起。诊断保留目标地址、端口、libuv 错误名和原因。
明确记录连接 ID 与原生句柄的差异和读半关闭边界。迁移分步提交，可回退到原补丁实现。

## 未决问题与完成摘要

版本范围已确定，无阻塞版本规划的未决问题。实现时仍须验证读半关闭平台行为、缓存上限、
stdin 阻塞读取销毁及 worker 迁移压力场景；这些是实施与验收任务，不能作为已经解决的事实。
已实现 `skyuv_client_runtime`：loop 在专属线程内创建、使用和关闭；调用者经互斥锁、
条件变量及 uv_async 提交并等待命令，命令状态不依赖 uv_async 唤醒次数。
重复生命周期测试执行 100 次创建销毁、2000 次命令，验证线程隔离、错误结果传递、
无效参数、未关闭 handle 收尾及重复销毁。尚未接入 TCP、Lua、stdin 或平台读半关闭，
客户端当前行为仍由原实现提供，不能宣称 beta.3 已完成。
