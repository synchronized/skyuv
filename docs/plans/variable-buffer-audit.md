# Skynet 可变缓冲区审计

## 状态

已完成。

## 背景

为使 Skynet Actor 核心可由 MSVC 编译，当前补丁将 7 个 C99 VLA 改为 `alloca`。该改动保持了原有的栈上临时缓冲区语义，但 `alloca` 不是 C11 标准接口，也不能报告分配失败。更重要的是，这些缓冲区的尺寸都没有代码级上限，因此当前方案只应作为移植基线。

本审计只分析尺寸来源、所有权、生命周期和失败路径，不修改运行时代码。

## 总体结论

- 7 个缓冲区的尺寸均来自字符串长度，没有任何显式上限；
- `NAME`、`LAUNCH` 和 `SETENV` 的参数可由 Lua 字符串直接传入，不能视为可信小输入；
- `cpath`、模块名和 `logpath` 通常来自配置，但配置层同样没有长度约束；
- 所有缓冲区都只在当前函数调用期间使用，不需要跨调用保留；
- 所有调用点都不适合长期保留无上限的 `alloca`；
- `_try_open` 还把两个 `size_t` 长度之和保存到 `int`，存在截断或溢出风险；
- `cmd_name` 同时分配两个 `size + 1` 缓冲区，最坏栈占用约为输入长度的两倍。

## 逐项审计

| 位置 | 数量 | 尺寸来源 | 所有权与生命周期 | 风险 | 建议 |
| --- | ---: | --- | --- | --- | --- |
| `skynet_module.c:_try_open` | 1 | `strlen(cpath) + strlen(module_name)` | 函数内临时路径，仅传给动态库打开函数 | 无上限；`size_t` 转 `int`；加法可能溢出 | 使用 `size_t` 检查加法后堆分配，函数退出前释放 |
| `skynet_module.c:get_api` | 1 | 模块名长度加固定 API 后缀 | 函数内临时符号名，仅供符号查询 | 模块名来自服务启动参数，无硬上限；每个模块加载调用 4 次 | 由 `open_sym` 复用一个堆缓冲区 |
| `skynet_server.c:cmd_name` | 2 | 每个均为完整参数长度加一 | 函数内解析结果；注册函数在返回前消费字符串 | Lua 可传入任意长度；双倍栈占用；`strlen` 结果转 `int` | 改为单份可写副本并原地切分，校验格式后释放；避免 `sscanf` |
| `skynet_server.c:cmd_launch` | 1 | 完整命令参数长度加一 | 可写副本；模块名和参数只需保持到 `skynet_context_new` 返回 | Lua 可传入任意长度；属于服务管理路径 | 堆复制，调用结束后释放，并定义无效输入行为 |
| `skynet_server.c:cmd_setenv` | 1 | 当前按完整参数长度加一，实际只需键长度加一 | 键只需保持到 `skynet_setenv` 返回；Lua 会复制键和值 | Lua 可传入任意长度；当前分配量可能远大于键长度 | 先定位分隔符，只按键长度堆分配；调用结束后释放 |
| `skynet_log.c:skynet_log_open` | 1 | `strlen(logpath) + 16` | 临时文件名，仅供打开文件和错误日志使用 | 配置无硬上限；路径长度还受平台文件系统规则影响 | 检查加法后堆分配；打开与日志输出结束后释放 |

## 所有权边界

- `skynet_module_init` 会复制 `cpath`，模块系统长期拥有该副本；`_try_open` 生成的完整路径仍只是临时值。
- 模块加载成功后会复制模块名；`get_api` 生成的符号名不会被动态加载接口长期持有。
- `skynet_command` 不复制参数。Lua 绑定提供的字符串只保证在 C 调用期间有效，因此命令处理函数必须在返回前完成解析或自行复制。
- `skynet_setenv` 最终通过 Lua 字符串保存键和值，调用完成后不依赖 `cmd_setenv` 的临时键缓冲区。
- `fopen` 和错误日志调用不会在返回后持有文件名指针。

## 推荐实施策略

1. 引入仅供补丁内部使用的安全尺寸加法检查，拒绝 `SIZE_MAX` 溢出。
2. `_try_open`、`cmd_name`、`cmd_launch`、`cmd_setenv` 和 `skynet_log_open` 使用 `skynet_malloc`/`skynet_free` 管理临时缓冲区。
3. `get_api` 属于低频模块加载路径，但会连续调用 4 次；让 `open_sym` 复用一块缓冲区，避免为了微小收益保留无上限栈分配。
4. 删除 `skyuv_alloca.h` 强制包含及所有 `alloca` 用法，使补丁只依赖标准 C11 与 Skynet 分配器。
5. 显式处理分配失败。当前 `skynet_malloc` 映射到系统 `malloc`，可能返回空指针；各函数必须返回失败并保持已有状态不变，不能解引用空指针。

不建议统一采用“固定栈缓冲区加超限堆分配”。这些路径不是消息派发热循环，减少少量堆分配的收益有限，却会增加分支、清理路径和测试组合。

## 实施验证

- 为 7 处路径增加正常输入、空输入、格式错误和长输入测试；
- 至少使用 64 KiB 参数验证不再依赖线程栈容量；
- 验证分配尺寸加法溢出会被拒绝；
- 验证模块加载失败、符号缺失、日志文件打开失败时没有泄漏；
- 在 Windows MSVC、macOS Apple Clang、Linux GCC/Clang 下构建；
- Linux 使用 AddressSanitizer 或 Valgrind 验证错误路径，保留现有 ThreadSanitizer 回归；
- 确认补丁只应用到构建目录，`3rd/skynet` 子模块保持干净。

## 后续决策

替换范围和所有权边界已经明确。实现采用可恢复失败：分配失败时返回现有失败值，并确保不会留下半初始化的模块、环境变量或日志状态。

## 完成记录

- 7 个 VLA/`alloca` 缓冲区均已改用 `skynet_malloc`/`skynet_free`；
- `_try_open` 改用 `size_t` 并检查长度加法溢出；
- `cmd_name` 改为单份可写副本原地切分，不再使用两个等长缓冲区；
- `cmd_setenv` 只分配键名所需空间；
- `open_sym` 复用一块符号名缓冲区完成 4 次查询；
- 删除 `skyuv_alloca.h` 及其构建强制包含配置。
