# v0.2.0-beta.4：Windows 构建诊断治理

## 状态

规划中，尚未开始修复或发布。承接未发布 beta.2 的诊断治理范围；当前已发布版本仍为
`v0.2.0-beta.3`，本轮不修改 CMake 版本号。

## 固定范围

实施 [010：Windows 构建诊断治理](../plans/010-windows-build-diagnostics.md)：

- 全量采集 Windows MSVC、clang-cl、Clang Debug/Release 的诊断，区分自有、第三方和 SDK 来源。
- 优先处理 Windows Clang 的 libuv CRT 弃用提示和未使用静态函数，消除随附诊断上下文噪声。
- 处理 cmocka 编码问题，审查既有 MSVC 未初始化、移位、窄化及符号转换诊断。
- 每项给出修复、保留或局部例外结论，记录理由、作用范围和复查条件。

当前用户日志仅见 libuv 18 条警告（10 条 CRT 弃用、8 条未使用函数）及 46 条 note，
末尾截断，不能作为完整基线或构建成功证据。完整采样是实施第一步。

## 处置边界

CRT 诊断先审查调用边界，再决定是否仅对 libuv 定义 `_CRT_SECURE_NO_WARNINGS`；
未使用函数优先通过补丁补充 unused 标记，必要例外仅限定 Windows Clang 的 libuv 目标。
不全局关闭警告、不降低等级、不关闭 skyuv 警告即错误，不直接改动第三方工作树。
不机械替换 `_s` 函数或增加未经证明安全的类型转换，不承诺第三方全部零警告。

## 发布门槛

- 六种 Windows 构建组合完成配置、全量构建和相关 CTest。
- 具备修复前后清单；编码、CRT 和未使用函数诊断已处理或有明确保留依据。
- 高风险诊断全部有审查结论，真实缺陷有复现测试及适当的重复验证。
- 自有目标严格警告策略不变，第三方源码工作树干净。
- 相关 Linux/macOS CI、三平台发行包及 SHA-256 验收通过，发布记录一致。

不包含依赖升级、客户端新功能、性能基线、路径约定或正式 v0.2.0 收口。
