# v0.1.0：Beta 后续收口

## 状态

**准备中，尚未发布。** 本版本承接 `v0.1.0-beta.1` 的跨平台运行时，目标是完成正式发布前的
性能、路径约定、CMake 消费和发布闭环。0.x 阶段仍不承诺稳定 ABI。

## 版本目标

在 Beta 已完成三平台运行时和候选发行包的基础上，补齐正式发布所需的权威性能证据、运行时路径
契约、外部 CMake consumer 验证和发布记录。

## 固定范围

| 计划 | 本版本收口内容 | 完成条件 |
|---|---|---|
| [006 性能和稳定性](../plans/006-performance-stability.md) | 固定 Linux Runner 的两轮权威性能基线和首批回归阈值 | 采集环境、参数、统计结果和差异记录完整 |
| [007 跨平台交付](../plans/007-cross-platform-delivery.md) | 将候选 Beta 收口为正式 Release | 版本、归档、校验和、三平台交付测试和发布记录一致 |
| [008 配置、日志与 PID 路径约定](../plans/008-runtime-paths.md) | 明确安装树、可写目录和兼容迁移行为 | 计划从草案进入实施并完成跨平台验收 |
| [009 CMake 第三方消费与 Lua C 模块接入](../plans/009-cmake-consumer-integration.md) | 完成安装 package、嵌入式消费和 Lua C 模块接入闭环 | 独立 Lua 解释器真实 `require` 至少在一个平台通过，计划完成记录补齐 |

## 不进入本版本

- 稳定公共 ABI、第三方 Lua C 模块二进制兼容和 Skynet 内部头文件承诺；
- Windows MSI、macOS PKG/DMG、代码签名、公证、自动更新和 Windows Service；
- 未经数据支持的性能优化或预先承诺的吞吐、延迟比例；
- 新增 Actor 调度模型、网络语义或 libuv 替代 Skynet 调度器的架构改动。

## 当前剩余任务

以下任务是本版本的收口清单，详细步骤仍以对应计划为准：

1. 部署带 `skyuv-benchmark` 标签的固定 Linux Runner，完成两次独立时段性能采集，并形成回归阈值。
2. 将 008 从草案推进到实施，确定配置文件、日志和 PID 的安装目录、可写目录、覆盖方式和迁移说明。
3. 为 009 增加独立 Lua 解释器加载已构建模块的真实 `require` 验证，并补齐计划完成摘要和记录链接。
4. 在拟发布提交上重新运行 Release workflow，验证三平台归档、SHA-256、版本标签和 GitHub Release 内容。

## 发布门槛

- 006、007、008、009 的验收条件全部满足，或明确记录不影响正式发布的遗留限制；
- Windows、Linux 和 macOS Release workflow 通过；
- 安装树、CPack 归档和外部 consumer 不包含源码树、构建树或本机路径；
- Changelog、版本文档、发布记录和 GitHub Release 使用同一版本、提交和限制说明；
- 正式标签只能指向完整验收提交，不能移动已公开的 Beta 标签。

## 版本身份

正式版本身份仍由根目录 `CMakeLists.txt` 和 Release workflow 校验。准备正式发布时，应将
`SKYUV_VERSION_PRERELEASE` 清空、更新 Changelog 日期和发布记录，并使用 `v0.1.0` 标签。
